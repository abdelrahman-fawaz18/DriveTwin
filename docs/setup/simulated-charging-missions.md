# Measure charging missions in the local simulator

The mission runner starts one bus at rest on a reviewed mission edge. It measures route changes, stationary charger energy, the battery target, resumed motion, and arrival at the mission finish. A correlation ID connects the fixture's diversion request with the later measurements. The simulator owns the battery state. The collector checks it against measured draw and charger input at each step. [Charging policy](../charging-policy.md)

The nominal comparison starts each arm with the same road network, seed, 54 kWh, 8 kW equipment assumption, and bus charge acceptance. The advisor and nearest-feasible arms use the same initial observations and catalog and apply an operator-approved fixture diversion. The native Stationfinder arm controls its own route and stop. Its rescue action is disabled, and all arms terminate on observed reserve violation, depletion, collision, or relocation. A no-charge arm measures the original mission time for the delay calculation. [SUMO Stationfinder settings](https://eclipse.dev/sumo/docs/Simulation/Stationfinder.html)

The nominal fixture deliberately requests a charging comparison. Its 34 kWh continuation estimate is an input scenario assumption. The no-charge control finishes above reserve. The advisor and nearest arms aim for 87.5 kWh. Stationfinder receives a 25% saturation setting and calculates its own departure energy, so the measured native completion time includes that policy difference. The nominal fixtures share initial conditions. The later [dynamic comparison](registered-charging-and-dynamic-comparison.md) matches physical outages and the reserve cutoff. Equal queue information, a shared delayed-status feed, and moving custom replanning remain outside that result.

The first attempt detected a battery accounting mismatch when leaving a charger. SUMO 1.28 can retain the last charger reading while the vehicle moves off its lane. The collector keeps both the reported value and stationary-only charge in the trace. Battery energy must still reconcile with draw and stationary charge after resumption. A charger supplies positive energy only at the observed stopped location in this fixture. The measured pack-side charging rate reflects SUMO's parking behavior, including the zero auxiliary draw observed during the parked interval. The offline estimate retains its separate equipment assumption. [Pinned SUMO battery source](https://raw.githubusercontent.com/eclipse-sumo/sumo/v1_28_0/src/microsim/devices/MSDevice_Battery.cpp)

The protection cases verify the local diversion gate before a route change. Operator override, thermal and local protection, stale departure data, simulation expiry, and missing automatic approval each leave the route and battery charge untouched. The gate binds each request to the model, decision, departure observation, run, and bus. It checks both simulation validity and a monotonic lease, which is a short real-time deadline that survives changes to the displayed clock. The thermal flag is a fixture input for testing precedence. These tests use the isolated simulator, with the HTTP service and PostgreSQL claim path as a separate integration checkpoint. [Phase 3 command boundary](../adr/0056-close-local-command-scope.md)

The adverse cases exercise an outage, all stations blocked, and unexpected battery draw. The outage arm removes the unavailable charger from the simulator, selects the alternate station, and measures the resulting charge and mission completion. The blocked arm remains at the departure point. The unexpected-draw arm runs with an injected load beyond the forecast's qualified domain and stops collecting the mission when measured energy falls below reserve. That run counts as incomplete.

Open PowerShell in `<checkout>` and choose a new output folder. The launcher runs the pinned simulator image without external network access. It uses a read-only project mount and writes results under the private evidence folder. [Launcher guide](linux-launcher.md)

```powershell
python scripts/linux.py --timeout 240 -- docker run --rm --network none --read-only --memory 512m --tmpfs /tmp:size=128m,mode=1777 --mount type=bind,source=<checkout>,target=/workspace,readonly --mount type=bind,source=<checkout>/evidence/p4,target=/output -w /workspace -e PYTHONPATH=/workspace/src evdt-energy-collector:p2 /app/.venv/bin/python -m scripts.charging.run_charging_missions --output /output/my-charging-missions
```

Expect four nominal arms, six refused commands, and three adverse cases. Read `qualification.json` for terminal reasons, observed energy, delay, and outcome for each arm. Each simulator folder contains its route and charger configuration, measured trace, and result. A refusal or deliberately interrupted mission appears as incomplete. The fixture qualification passes when those adverse outcomes match the test expectations.
