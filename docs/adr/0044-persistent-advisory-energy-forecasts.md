# ADR-0044: Persistent advisory forecasts and scoped product views

Date: November 4, 2026. Status: implemented and passed within the scope recorded in `docs/verification/energy-product.json`; final P2-E1 promotion remains open.

Keep the qualified one-request calculation worker and its image contents, limits and network/file denial unchanged. A trusted host controller obtains a bounded, asset-authorized observation view from the existing monitoring API, verifies the frozen model release, prepares the historical assumed plan and scenario envelope, and invokes the existing isolated worker. It never asks the worker to read databases, source recipes, simulator state or future outcomes. The controller is trusted infrastructure, not part of the denied worker boundary. No Docker socket is mounted in an application container.

Provision an explicit per-run/asset/source assignment as an administrator. Bind the known route, source identity, independent declared capacity/reserve and frozen release. An absent assignment is unavailable. Source mode, clock, epoch/session, quality, sample age, gaps and route identity come from registered server data, not an HTTP caller's declarations. External charging exclusion is an explicit operator/source-configuration assumption; it is not a measured charging detector. Only simulation is supported. The frozen accuracy study covers a prediction at 120 simulation seconds on this route; other cutoffs are visibly outside this evaluated domain. Do not silently extend qualification or promote generic worker labels. Product forecasts remain advisory pending P2-E1.

Add an append-only forecast table, distinct from observation tables, and a narrowly privileged forecast writer. Readers retain SELECT-only access. Forecast writers cannot change observations, clocks, assignments or existing forecasts. Store unavailable outcomes as well as available estimates, with input event/wire references, source-clock identity, assignment/release/job fingerprints, numerical version, assumptions and empirical scenario bounds. A duplicate identity must have identical content; conflicting content fails. No user-facing POST route, command, automatic charging or dispatch is added.

Use existing asset reader authorization on bounded latest/history/detail endpoints. Recheck current clock, latest observation, assignment and input age at read time: an old numeric forecast must not look current after a pause, disconnect, source restart, newer missing measurement or lost configuration. Keep the historical record intact while suppressing current prediction values. Separate unavailable, stale and disconnected presentation from an actual predicted energy deficit. Browser input validation, cancellation on asset change, bounded polling and a response-age watchdog prevent mixed-asset or indefinitely fresh displays.

Use a small Compose overlay and a manually launched, bounded controller command. The writer service has only its own database secret; the calculation worker still has no mounts or network. The existing monitoring deployment remains usable with forecasts unconfigured. Record and verify migration/backup compatibility and role denial. Reuse the original frozen datasets and model evidence without re-opening or regenerating held-out trials. Verify new behavior with deterministic observations, actual isolated worker calls, a small real database/API/browser session, affected regression checks, and final shared checks after source stabilizes. No capacity/soak run is required for this functional integration.

Raw inputs, jobs, worker outputs, source identities, credentials, browser artifacts and diagnostics remain ignored. Only independently authored code, synthetic policy, reviewed aggregate results and digest references are commit candidates.

The corrected controlled integration passed. Its first producer timestamp-format failure remains failed. The dedicated input-purpose credential was denied general reader access; the current browser check passed after a CSS-only layout correction. Exact source comparison preserves the full backend/restore report and records that only presentation and the focused-check controller changed afterward. No numerical, model, threshold, worker or database/auth behavior changed after the full pass.

Exact-byte Git storage is also applied narrowly to five preexisting files whose qualified CRLF bytes previously differed from LF-normalized Git blobs. Their physical working bytes, semantics, fingerprints and all test results remain unchanged. All qualified source bytes must match staging and checkout filters; no source guard or immutable fixture is relaxed.
