# ADR 0054. Preserve command history through changes and recovery

An operator may cancel a pending speed command. In the direct operator profile, the operator may also replace it with a new command ID and valid request. The service takes the same PostgreSQL transaction lock for a change and a simulator claim. If the change commits first, the original stays closed. A concurrent claim can receive the replacement. If the claim commits first, the service rejects the change and preserves the original reservation. Cancellation and replacement retries preserve the original record, including its change time and successor link. A canceled command ends the run's direct command chain. A sealed arbitration decision can be canceled before handoff and remains an immutable decision. A new arbitration decision requires a fresh run.

An operator mission intent records a destination request for a hypothetical station. The command initializer admits the station list only when its fingerprint matches the registered run and bus. The API checks the intent's run, bus, mode, station, and short admission deadline. It stores the original bytes and reports `intent_recorded`. Mission records are separate from speed commands and have no executor handoff. Route changes, reachability checks for dispatch, and charging remain Phase 4 work.

The local backup saves a stopped database as a PostgreSQL custom archive. Restore into a separate empty cluster using a single transaction and new credentials. Compare table contents, constraints, database permissions, generated-number counters, and API records before using the restored database. An old reservation or canceled decision remains closed. The qualification restores a direct replacement with a measured result and a canceled arbitration decision, each with an accepted mission intent. [Run guide](../setup/command-operations-check.md)
