# ADR 0048. Reconcile an interrupted speed command from observations

The reservation remains the one-time handoff boundary. An executor that loses a response cannot obtain a second copy by asking again. PostgreSQL keeps the reservation across service replacement and database restart. An execution result remains optional and retains its original meaning.

Add an independent observation record for the bounded speed-cap exercise. A separate observer process has its own credential and reads the baseline and commanded speed traces. It supplies the actual measurements, command ID, run and asset. It has no operator or executor credential and cannot claim a command or submit an execution result. The server checks the scope against the reserved command, reads the original limit, and computes the assessment from the observations. It saves the evidence and assessment in a separate append-only table. Identical evidence retries return the same record. A different submission for the same command conflicts.

For the reviewed run, require one good `motion.speed` measurement per simulated second from 1 through 16 and identical speeds through second 4. Compare seconds 6 through 16 after a short settling interval. The baseline must exceed the cap by more than 0.25 m/s on at least two comparison samples. Confirmation then requires at least two corresponding commanded readings within 0.05 m/s of the cap or below, and every commanded reading in the comparison window must respect that tolerance. If the baseline is informative and the compared values match, report `not_observed`. Incomplete evidence is rejected. Uninformative or conflicting measurements yield `inconclusive`.

Keep the execution state and effect assessment separate. For example, `unknown_outcome` with effect `confirmed` means the journal has no execution reply and the measured speed change supports the requested cap. `not_observed` applies to this bounded trace and leaves an uncertain execution reply uncertain. No state grants another handoff.

The recovery test terminates only a disposable command transport process. It can lose the returned claim before actuation, lose the execution result before publication, or lose the result acknowledgment after PostgreSQL commits it. The simulator stays alive so the speed sensor can finish the trace. The test then restarts the command service and PostgreSQL before reconciling the result. This covers transport interruptions in the local simulator path. Restarting or restoring the active plant, authority conflicts, and operator interface integration have their own Phase 3 scope.
