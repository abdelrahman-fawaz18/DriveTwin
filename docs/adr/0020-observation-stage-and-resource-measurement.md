# ADR-0020: Observation-stage, clock, browser and resource measurement

Status: selected for P1-E2-B; measured acceptance is recorded separately.

## Boundaries

E2-B implements collectors and short paced rehearsals. E2-C retains the full warmup/W0/W1 durations and concurrency. Neither a short run nor instrumentation unit tests pass those workloads or Q-12 at W1.

Use the existing actual source, durable queue, authenticated transport and transaction path. Optional local tracing writes bounded JSON Lines files (one complete JSON object per line), with sequence, process identity, Linux boot identity, wall and monotonic timestamps. Logs contain correlation metadata and byte fingerprints, not readings, payloads or credentials. Tracing is off unless an administrator supplies a private writable destination. A failed enabled collector invalidates qualification; do not silently replace missing records with zeros. Tracing adds overhead; results describe the instrumented stack.

Sample-ready time is captured immediately when the model yields a sample, before durable enqueue. Bind it to the event identity after enqueue succeeds; pass the same wall timestamp as observed_at. Record enqueue completion, every publish attempt/return, broker acknowledgment, receipt application, receiver callback, projection staging and transaction completion. Projection staging occurs inside the same transaction as history/current/receipt; it is not independently durable. Transaction completion is a conservative upper bound after the database commit returns. An insert-time database default is not mislabeled as the completed commit. Repeated delivery attempts remain separate from unique-event dispositions.

The browser collector observes actual measurement-row attributes after React commits the element tree (DOM). It verifies all 20 displayed values/units against actual source packets before accepting an event. Network-response time alone is insufficient. The first paced browser attempt preserved the original one-second coalescing stream and exposed missing displayed events (75 and 74 of 90 in Edge). Preserve this failed result. Select a 250 ms refresh budget and subtract actual query/serialization elapsed time from the wait, removing the old accumulated extra delay. This remains a replacement-snapshot display, not a promise to replay every intermediate state under arbitrary overload. Missing events still fail; no denominator, source cadence, freshness deadline or latency threshold is relaxed. Requalify actual complete-event rendering and the original functional browser paths.

## Clocks

An authenticated read-only clock exchange returns Linux receive/send UTC and monotonic timestamps and boot identity. Browser and Windows collectors take bracketed before/periodic/after exchanges. Use every declared exchange in the strict offset diagnostic; inconsistent global intervals or uncertainty above 50 ms make that cross-clock method inconclusive. Clock steps, unsupported local domains and excessive sampling gaps invalidate the corresponding collectors. The selected primary local-clock bound is specified below. Never subtract unrelated monotonic origins. Linux and Windows wall-versus-monotonic changes are watched throughout. Endpoint timing and collector scheduling overhead remain part of uncertainty. Add conservative uncertainty to latency percentiles.

## Resources and test ownership

Sample Linux container cgroup memory/stat/limit/OOM counters, whole-Linux memory, and swap-counter deltas once per second. A cgroup is the Linux accounting boundary for a container. Sum only disjoint owned application groups, including sources and senders; keep test helpers separate. Sample Windows available physical memory, system paging and aggregate browser/WSL process working sets separately. A working set is physical memory currently attributed to a process. It is not interchangeable with cgroup charge or host available memory. Browser process-name totals can include other open sessions and must be labeled.

The short rehearsal uses two actual sources concurrently for each qualified browser, separate asset pairs, 60 seconds of warmup and 30 measured seconds per source. All source events, including warmup, must reconcile; percentile denominators for the measured window exclude the warmup explicitly. Collect and preserve resource traces, but do not claim full W1 resource acceptance. Synthetic negative tests must reject missing/corrupt/duplicate/out-of-order trace records, missing DOM events, invalid clocks, counter resets, OOM and incomplete resource coverage.

Keep Windows-native agent mode, one canonical tree, original contract/catalog bytes and migrations. Preserve historical D2/E2-A guards; add an exact reviewed E2-B guard for necessary instrumentation changes, and run affected monitoring/quality/history/replay/browser regressions. Raw logs, machine/process details, tokens, screenshots and generated controls remain ignored. No remote collector or dependency is added.

The Windows process collector uses PROCESS_QUERY_LIMITED_INFORMATION, as supported by [Microsoft GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo). It records unreadable process counts; an unavailable working set must not be published as a measured zero. PDH uses the [official English-counter API](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhaddenglishcounterw); a missing counter fails collection.


## Causal DOM timing and clock qualification

The constant-offset hypothesis failed in the early instrumented attempt: before/periodic/after offset intervals did not all overlap, and some conservative unions exceeded 50 ms. Preserve this inconclusive result. Keep the strict constant-offset helper and its tests; do not relabel those clocks synchronized or drop inconvenient exchanges. Browser network interception also added avoidable clock-request delay; use passive request auditing under the existing same-origin policy for the measurement test.

Select a causal upper bound for primary source-to-DOM timing. Immediately after the observer verifies all 20 rendered rows, it sends an authenticated clock request bound to that asset/event. The Linux handler echoes the identity and its receive timestamps; it neither stores an observation nor issues a command. Source-ready and witness-receive timestamps share the qualified Linux monotonic/boot domain. The latter is after verified DOM availability, so their difference is a conservative upper bound including the return-path overhead. Record browser DOM-to-request-to-reply elapsed time as confirmation overhead, separately from clock-domain uncertainty. The frozen 50 ms limit remains mandatory for cross-domain estimates; the selected primary measurement uses one local clock as explained below. Missing/late/mismatched witnesses fail. Do not add uncertainty a second time to an already conservative upper delay.

Mandatory periodic exchanges still verify coverage, boot identity, local elapsed-clock consistency and wall-clock steps. The separate strict global constant-offset diagnostic may remain inconclusive; publish that status explicitly. Do not use it to subtract unrelated clock origins. This follows the frozen rule to report bounded error and use local intervals when cross-host synchronization is unsuitable. It introduces no assumed drift-rate tolerance and preserves all source events and latency thresholds. Full W1 remains E2-C.

WSL's protected process could not be read through an ordinary process handle. The collector uses the existing PDH Process(vmmemWSL) Working Set counter, marks absent readings as unavailable and requires coverage during active rendering. Raw direct-query failures are separate diagnostics, not measured zeros. Record Windows host headroom failures independently of container memory and collector correctness.


## Clock error versus conservative witness overhead

The first causal prototype incorrectly applied the 50 ms cross-clock uncertainty limit to the entire confirmation round trip. Preserve that failed prototype. A return-path delay is measurement overhead, not an offset between timestamp domains. The selected primary bound never subtracts a Windows timestamp from a Linux timestamp: both source-ready and witness-receive are sampled from the same qualified Linux monotonic clock. For the actual event ordering S (sample ready), D (verified DOM read), R (server receipt), S <= D <= R, so R-S upper-bounds D-S. Added return-path delay can only make the reported result worse. A passing percentile of these upper bounds therefore proves the corresponding percentile limit without estimating or subtracting the extra delay.

Report confirmation round-trip/dispatch overhead separately, including values above 50 ms, and retain a ten-second missing/measurement deadline. Measure and record the local monotonic clock's resolution; reject an unsupported/coarse local timing domain. The frozen 50 ms rule remains unchanged for any cross-domain timestamp estimate: the strict constant-offset diagnostic stays inconclusive when it cannot satisfy that rule, and it is never used for the primary bound. Publish the primary result as an upper bound, not an exact screen-render latency or a newly synchronized-clock claim. This is the plan's allowed local-interval method, not a relaxed latency objective. Protocol 1.1 adds explicit local clock resolution to the trace header and clock reply.
