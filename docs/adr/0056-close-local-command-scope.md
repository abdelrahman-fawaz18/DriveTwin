# ADR 0056. Close the local command milestone with explicit recovery boundaries

Phase 3 qualifies a single simulated bus with a bounded speed cap and a recorded station intent. The evidence review passed the six local command integrity criteria. This decision completes the deliverable review and states where the implemented architecture differs from the project-wide command design. [Phase 3 evidence](../verification/command-closeout.json) · [Deliverable closeout](../verification/command-acceptance.md)

**Dispatch.** Retain the authenticated HTTP claim for the local profiles. The queued PostgreSQL request is the durable dispatch record, also called an outbox. It survives a service restart, and the service commits a unique reservation before returning command bytes. The simulator applies local checks before acting. The monitoring message broker still carries telemetry and its delivery receipts. A broker-based downlink is a design option to evaluate before changing transport or deploying remotely. Any new transport must preserve authenticated scope, time limits, a single handoff, audit, and separation from replay. The Phase 6 integrated tests must qualify the transport actually used.

**Restart.** Retain the coordinator reservation and result journal plus the executor's in-process duplicate check. If the simulator disappears, the old reservation stays closed and an unresolved execution stays unknown. The live source refuses to resume the same run and requires a fresh run with a separate identity and queue. The database keeps the interrupted run. A durable device-side ledger and recovery of the same plant session are open. Before enabling either same-session recovery or control of a physical device, qualify persistence of device command IDs and outcomes, reconcile them with independent observations, and prove that a repeated command after restart causes at most one effect. Phase 6 still tests executor and coordinator restarts under the declared recovery behavior. Phase 8 owns the physical adapter's persistence and outage proof. [Live restart decision](0052-refuse-unsafe-simulator-restarts.md)

**Automatic authority and decision records.** Phase 3 demonstrates role precedence, one sealed decision per run and bus, and rejection of a stale authority number. It uses fixture proposals for the thermal and energy roles. Continuous arbitration or active coordinator takeover needs its own qualification before either is used. A Phase 4 automated proposal must identify its policy and model versions, input observation or forecast references, applicable preconditions, validity limits, and a correlation ID connecting admission, execution, and observed effect. Derive priority from trusted authority and retain the decision rationale. Add and test this in the versioned charging path before enabling automatic dispatch. Preserve old command schemas and records. [Live authority decision](0053-verify-live-command-authority.md)

Phase 4 can start with charging requirements, station configuration, and offline advisory design. The Phase 2 release establishes a bounded known-route forecast and assumed-plan station assessments. A measured station-arrival result, model qualification for the intended runtime domain, and explicit dispatch approval remain open.
