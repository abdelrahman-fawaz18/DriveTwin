# ADR 0057. Define the local charging advisor before authorizing dispatch

Use a separate versioned station catalog for Phase 4. Preserve the two Phase 2 station positions, its navigation data and its qualified advisory release. Add an explicit lane stop interval, synthetic connector labels, charging power, bays, waiting capacity and status age for each Phase 4 site. Keep the current status separate from static configuration so an outage can affect one run without editing the site definition. The three initial sites are hypothetical. Their geometry is checked against the pinned bus road network. [Catalog](../../simulation/montreal/charging-stations-1.0.0.json) · [Setup guide](../setup/charging-station-profiles.md)

Use a provisional 10% reserve and 25% charge target in the bounded simulated scenarios. Exclude incompatible, unavailable, unreachable or reserve-violating stations before ranking by predicted added mission time. Use an explicit no-feasible result. Write the reason and the input identities with each recommendation. Preserve authorized operator override and local protection when the command path is added. This resolves D-12 for the offline/advisory design. Operating-domain limits and numerical station-arrival qualification are open. The proposed and baseline policies must use comparable information and preserve adverse outcomes. [Charging policy specification](../charging-policy.md)

Move to station-arrival qualification design and reference drives next. Any automatic dispatch requires qualified runtime inputs and a measured model domain, correlated effects, protected authority, and explicit approval. A successful static road check establishes a usable simulated approach for evaluation. It does not establish physical station access, stopping behavior, energy accuracy, or charging.
