# ADR-0045: Complete advisory mission explanations and station assessments

Date: November 4, 2026. Status: implemented; scoped E1 acceptance and final advisory review passed November 5. See the [closeout](../verification/energy-advisory-acceptance.md).

Preserve the frozen numerical/point-worker/calibration sources, B2/C1 manifests and consumed held-out evaluation. Complete original Phase 2 requirements without fitting again, rerunning that evaluation, introducing another framework or enabling commands.

Add versioned optional explanation/station extensions to the existing immutable composite record. The existing JSON database representation and 1.0.0 core fields admit additions; old records remain byte/content-identical and old clients ignore unknown fields. New readers validate extensions when present and explicitly identify missing legacy metadata. Show latest input wall-clock age separately from forward simulation-time/distance horizon. Display the existing conditional recent-consumption distance/time to the declared reserve, independently labeled from the route prediction, and concrete capacity/mass/equipment/motion assumptions.

Generate a public static navigation profile from the existing reviewed Montreal network using the pinned SUMO tools. No physical vehicle, energy state or future traffic is simulated. Snap the two hypothetical stations to explicit bus-allowed road approaches within a declared offset bound. Preserve the actual station coordinates and label the approach separately. Precompute bus-class legal paths, including internal connection lengths, from known-route road segments to those approaches. Record network/map/mission/station/source fingerprints and attribution. The geometry matcher uses current admitted location/heading, rejects remote/ambiguous points, and never turns straight-line distance into driving energy. Missing GPS prevents station assessment without invalidating unrelated route-energy quantities.

The trusted coordinator receives the additional permitted location/heading observations and the profile digest. The isolated calculation worker continues to receive only its original four observed quantities plus declared plans/parameters. Each station receives its own bounded assumed-motion job and path/input/model identity. Road access, modeled energy feasibility and minimum reserve along the whole assumed trajectory remain distinct. Behind-same-edge, no route, unmapped, mismatched profile and unusable location produce explicit unavailable results. Assumed speed/flat grade/equipment are visible. Station scenarios may show parameter-sensitivity bounds, explicitly without independently measured station-endpoint coverage; the frozen end-of-route accuracy numbers are not station-arrival evidence. No station ranking, selection, command or charger operation is added.

Use the existing small owned integration with current records, ordinary reads, access denial, legacy-record compatibility and fresh-cluster restoration. Add actual browser assertions for age/horizon/time/range/assumptions, station outcomes, missing required observations, unsupported cutoff, unavailable states and recovery. Keep the five-second latest-input age limit and original source/authorization restrictions. The controlled producer may create fresh registered test identities from retained training values; it never edits originals or regenerates held-out outcomes. Reuse current frozen numerical/accuracy proofs after exact checks, qualify affected behavior and run shared checks after stabilization.

Close the readiness checklist only from measured passing evidence for all original work, criteria and deliverables. Publish the advisory readiness decision as a separate release record and preserve the historical worker and model flags. Phase 2 can establish functionally verified assumed-plan station services and its bounded known-route accuracy study; it cannot approve real-bus accuracy or automated station decisions. Later decision policies require independent station/operating-domain evidence before relying on them. Phase 3 is not started by this work. Existing Phase 6 release gates remain unchanged.

Primary interfaces consulted: [SUMO road/position conversion](https://sumo.dlr.de/docs/TraCI/Simulation_Value_Retrieval.html), [SUMO shortest paths and internal-connector costs](https://sumo.dlr.de/pydoc/sumolib/net.html). Runtime behavior is verified against the installed pinned version.

The first application check exposed a timing problem: running four jobs in sequence could exceed the unchanged five-second input-age limit. Run up to four independent one-request containers concurrently with original per-worker limits, preserving exact output-to-job binding. This bounds worker memory caps to 1 GiB in total; the measured pass is a small functional check, not a host-capacity guarantee. The original failure remains separate from the corrected pass.
