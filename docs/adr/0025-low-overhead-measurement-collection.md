# ADR-0025: Bounded measurement overhead and direct container metadata reads

Date: November 4, 2026. Status: selected; fresh fleet qualification pending.

## Evidence and decision

Ten-asset rehearsals 06 and 07 completed source/service/browser value checks but failed complete resource coverage. Linux samples had gaps above the unchanged 1.5-second limit. Windows samples stayed near their one-second cadence, while available physical memory also failed its unchanged reserve. A temporary local log stage in attempt 07 measured writes around fractions of a millisecond and scans around 1.5 seconds; file staging did not address the measured bottleneck and was removed. Partial and failed attempts remain private and unpassed.

Attempt 08 used smaller CLI inspection responses and batched simultaneous source-exit rechecks. It still measured Docker listing/inspection delays above one second and failed resource coverage. Preserve it without retroactive acceptance. Do not remove slow samples, interpolate counters or change the clock/gap/headroom limits.

Use a persistent, project-scoped local Docker Engine HTTP connection for read-only metadata. Negotiate the daemon API within the client's supported range, currently through `1.56`, and record the actual selection. Retrieve only the exact Compose project's non-one-off container list and inspect its known full identities. Reject changed ownership, unknown/repeated identities, malformed state, missing responses, protocol/status errors and oversized responses. Read the same disjoint Linux cgroups and whole-Linux counters as before. Confirm source-exit races with fresh metadata and reject unreadable running groups. No new package, daemon setting, service or privilege is introduced. See [Docker Engine API/versioning](https://docs.docker.com/reference/api/engine/).

Retain direct private JSONL output, actual timestamps and sequence validation. Record collection/list/inspection/cgroup/recheck/write durations to diagnose overhead. A graceful interrupted collector closes its partial output and exits nonzero. It cannot turn an incomplete capture into a pass.

Attempt 09 still failed both resource coverage and host reserve: direct metadata inspection took about 0.82 seconds at two boundaries, producing gaps up to 1.813 seconds. Its 900-event displayed-value checks and private network archives passed; overall acceptance did not. The direct API is useful for bounded identity validation but is not sufficiently predictable inside this laptop's one-second collection loop.

For fault-free W0/W1 and their concurrency rehearsal, select `frozen-cgroup/1.0.0`. Initialize the exact active service graph after sources/senders start, while source sampling still waits at its common start barrier. Cache only container identities and kernel accounting locations. Signal readiness after the first complete counter sample, then release the sources. Read fresh kernel memory/CPU/event/paging counters every second without daemon metadata calls in that loop. Missing groups are explicitly absent, never fabricated zero usage or successful exits. Existing active source/sender/core coverage requirements remain in force. Before owned cleanup, independently inspect the full final graph: require identical full IDs, service ownership, start times and restart counts; running processes must retain their PIDs; require no OOM kills, normal completed source/migration exits and running persistent services. Save this bound final inventory and require it in the report. A graph change, unexplained absence or final-check failure invalidates the run. Dynamic paired fault-oriented collectors retain per-sample discovery. This policy is appropriate only to a declared fault-free immutable graph, not a general deployment monitor.

## Browser diagnostics

Use explicit `action-har/1.0.0` measurement diagnostics. Retain Playwright action/assertion traces, but disable automatic screencast images, duplicate page snapshots and bundled source copies during the measured run. Keep the viewport, actual per-asset DOM-value checks, per-event post-DOM witnesses, periodic clock exchanges, source/queue/attempt/broker/receipt/database traces, one-second resource samples and explicit end/failure screenshots. The explicit fleet-viewer policy is specified separately in ADR-0027. Ordinary functional and visual qualifications retain their original full tracing. The [pinned framework's tracing interface](https://playwright.dev/docs/api/class-tracing) exposes these options; installed source confirms that its built-in network tracing is coupled to page snapshots.

Therefore start a separate HTTP Archive, HAR, for each measurement context with response bodies omitted. A HAR records web requests, responses and timing metadata. It is diagnostic evidence, not a replacement for original observation bytes or displayed-value checks. Require complete, valid, nonempty archives in the final report. Stop and save them before publishing each browser result. Keep them private: headers may contain credentials. Generic `*.har` ignore rules complement ignored evidence directories and staged privacy/secret checks.

The profile, fixture, browser result and report bind the tracing and resource-collector policies explicitly. Earlier captures retain their original policies and cannot be relabeled as current-policy evidence. This is an instrumentation change with required fresh qualification; a lower-overhead collector is not itself a latency/resource pass.

## Unchanged gates

Phase 1 remains `phase1-wall-time/1.1.0`: 60 warmup plus 1,800 measured wall seconds per full W0/W1 attempt, with ten simultaneous W1 assets, 20 signals and one event per asset per second. All other quality limits remain, including complete event accounting, source/DOM equivalence, primary p95 <=2 s / p99 <=5 s, 1.5-second maximum resource gaps, six-GiB application budget, two-GiB host reserve with at most 30 consecutive seconds below it, and the existing swap/OOM conditions. Browser name-based working-set totals can include shared pages and other sessions; actual Windows available physical memory remains the host-reserve criterion. No process-memory estimate is subtracted to manufacture a pass.

Require shared/negative protocol and race tests plus new actual fleet measurements. Full W0/W1 and the remaining history/restore/storage/retention/startup/visual/audit gates remain open until their own matching-source evidence passes.
